# Protobot Rebuilt Context Map

This is the quick orientation document for both human contributors and coding agents. It describes the current repository rather than the historical release documented in parts of the README.

## Project at a glance

- Unity editor: `6000.6.6f1` (see `ProjectSettings/ProjectVersion.txt`).
- Active scene: `Assets/Scenes/Main.unity`.
- Rendering: Universal Render Pipeline (URP). The main 3D camera is the Base camera; `UICamera` is stacked as an Overlay camera.
- Primary macOS development build: `build.app`.
- Source namespace is mostly `Protobot`; older scripts in the project may still use the global namespace.

## Core interaction flow

1. `MouseCast` resolves the collider under the pointer.
2. A selector creates an `ISelection` and sends it to `SelectionManager`.
3. Selection responses update outlines, object links, tool availability, and state behavior.
4. A movement tool operates on the selected object or `MultiPivot`.
5. `ObjectElement` snapshots provide undo/redo state around the mutation.

The Connect tool is slightly different: it freezes the body set when activated, captures a source hole/body pivot and a target hole/body pivot, then applies the same translation delta to the independent movement roots. It intentionally does not rotate parts.

With Move/pivot (`2`) active, a single hole click selects its face and immediately starts the existing Move placement preview. `ClickSelector` starts `MoveToolManager` after selection responses finish, preserving the clicked face and Grouping Bypass scope. Body clicks still select normally. Placement ignores confirmation input on its starting frame so the source click cannot also commit the move; the next click places it.

## Default tool and camera bindings

| Binding | Action |
| --- | --- |
| `1` | Transform tool |
| `2` | Move/pivot tool |
| `3` | Color tool |
| `4` | Connect tool |
| `5` | Simulation tool; press again to show/hide animation controls |
| Mouse motion with a simulation driver selected | Scrub motion horizontally with viewport cursor wrapping; click sets the pose as one undoable edit, Escape/right-click reverts |
| `G` | Grab selected parts in the camera plane |
| `R` | Rotate a placed selection about the closest camera-facing world axis; during initial placement, Move or G → H, toggle rotation of the current preview |
| `X` / `Y` / `Z` during grab/rotation | Constrain to a world axis through the starting position; repeat to restore free grab or rotation's initial primary axis |
| Pointer reaches an editing-viewport edge during G + X/Y/Z | Wrap the cursor to the opposite side and keep moving continuously |
| `H` during grab | Switch to hole snapping; press H again for free movement, or X/Y/Z for an axis |
| Click / `Enter` during selection grab/rotation | Confirm as one undoable operation |
| `Escape` / right-click during selection grab/rotation | Cancel and restore the starting transforms; in H mode right-click orbits and Escape cancels |
| `P` | Pick the selected part's type and properties into normal placement |
| `Up` / `Down` | Increase / decrease the first (top) property during placement or on a single selected part |
| `Right` / `Left` | Increase / decrease the second (bottom) property during placement or on a single selected part |
| Hold `Space` over a hole | Use the opposite face of that same hole; release to use the hovered face |
| `/` during G/R or placement/Move/G → H rotation | Open relative numeric entry on the current axis; press again for a global value, then again to return to mouse control |
| `/` during unconstrained G | Enter a global `X, Y, Z` position directly; slash again returns to mouse control |
| `H` outside grab | Toggle grid visibility |
| `J` | Toggle holes only |
| Hold `Ctrl` (Bypass Snap) | Temporarily bypass snapping |
| Hold `Ctrl` (Select Multiple) while clicking parts | Add parts or connected assemblies to the selection |
| Hold `Command` (Bypass Grouping) while clicking a part/hole | Select that part individually, bypassing its connected assembly; the scope persists after release |
| Hold Duplicate (default `Alt`) when starting an axis drag or `G` / `R` | Leave copies at the starting pose while transforming the selected parts |
| Hold `Shift` | Noclip camera mode |
| Noclip `W/A/S/D` | Horizontal camera movement |
| Noclip `E/Q` | Move along the camera's screen up/down directions, including camera pitch |

Bindings are rebindable in Preferences. While noclip mode is active, its movement keys are captured so unrelated bindings do not also fire.

During G/R, physical X/Y/Z take priority over every conflicting binding, including rebound Grab, Rotate, grid, Duplicate, Snap Bypass and Grouping Bypass actions. Held conflicting actions stay suppressed until release. `Grab Hole Snap` is a separate rebindable input (default H), with a Preferences row; during grab it consumes conflicting inputs before their handlers run, including grid visibility. It is inactive during rotation and ordinary selection.

Grab hole snapping uses a selected hole face immediately, moving its connected/grouped set unless individually selected. For a multi-selection or body selection, H first accepts a source-hole click on the moving bodies. Holding Space picks the opposite face of that same source hole; releasing it restores the hovered face. The existing hover-hole marker highlights the exact source/target face, including the opposite side, and clears on invalid hits, camera navigation and mode exit. Hovering an outside hole or screw then translates and rotates the rigid set so the source face meets the target. Space uses the opposite hole face; screw targets retain their existing endpoint and orientation. Once a source is selected, `HoleMovePreview` replaces the solid moving renderers with a translucent combined mesh, uses `Assets/Materials/Hole Move Preview.mat` (also retaining the transparent URP shader variant in players), reuses Placement’s authored outline/animated fill, and displays the existing Move icon over the moving source face. It creates no colliders or movement pivots and does not leave a copy at the starting pose. The icon never intercepts input. Original renderer/outline states return on H/axis/numeric exit, confirmation, cancellation or disable; the preview stays visible through confirmation easing. `MoveTargeting` supplies one visible-target resolver and rigid face-alignment calculation for Move and keyboard hole alignment. Both use `MoveTargetPreview` for hole faces and a ring/axis tracker at screw endpoints. A screw targets the far face of its last stationary bore, falling back to its head anchor when no bore is hit; moving colliders are excluded from both the pointer ray and the screw’s endpoint query, preventing drift after snapping. Tracker updates follow live stationary geometry and clear with invalid targets, camera gestures and mode exit. Orbit (right mouse), pan (middle mouse), scroll zoom and Shift noclip remain available during both source picking and target snapping. Held camera gestures pause hole targeting/picking/confirmation at the displayed pose. Escape cancels H mode; right-click remains cancellation in free G/R. Numeric entry, settling and the confirmation frame continue to capture camera input. Target casts ignore moving colliders and reject sources outside the selection. Existing MultiPivots move directly. H again returns to free movement at the displayed pose. X/Y/Z and relative numeric entry always refer to the original grab anchor, including after H mode; selecting an axis projects back onto that original axis. The temporary source-hole pivot never replaces the operation's base position. Cancel restores the starting transforms; confirmation includes all mode changes in one undo step.

Automatic groups use symmetric live graph edges. A screw connects parts between its head and its furthest threaded hole. A shaft needs two distinct clamp bodies and includes only holes between the outermost clamps. Detector additions/removals are idempotent and enforce ownership; perpendicular holes cannot attach. Hole intersection checks also compare projected axial interiors so rotated, thick bores with real shaft clearance are not rejected merely because their world-aligned bounding boxes overlap. Every hole change refreshes the fastener graph after the frame, replacing previous membership even when counts match. Disabling/deleting holes, detectors or fasteners releases occupancy and connections; re-enabled geometry is detected again by physics. Graph traversal excludes inactive/deleted parts and resets at runtime startup.

`ISelection.individual` records the independent Grouping Bypass modifier when pointer selection occurs and follows hole selections, multi-selection membership, undo/redo and property regeneration. Selection links carry this scope to keyboard transforms, handle movement, duplication, Connect, outlines and move-tool previews; releasing the modifier does not silently re-expand the assembly.

Grab and rotation use the shared 0.5-unit / 15-degree snapping and Snap Bypass binding. Both ease toward their targets over 0.25 seconds with DOTween's standard easing, matching axis dragging. Confirmation lets the easing finish before capturing the exact final transform for undo; cancellation kills the tween and restores the starting pose. The shared rigid displacement is interpolated so multi-selection spacing stays fixed during rotation. Rotation starts on the nearest primary world axis (largest absolute camera-forward component), captured when R is pressed; it never rotates about an arbitrary camera axis. Initial placement, Move and G/H share `MoveRotation` and the existing `Rotate Placement` binding ID, labeled `Rotate Selection / Placement` in Preferences. R enters rotation about the chosen hole/screw axis and mating point, or the nearest camera-facing world axis through the current preview pivot when no target is locked. The target stays locked while the pointer rotates; R again resumes positioning, retaining the rotation. Click commits the placement/move, and Escape cancels. G/H retains the entire grab and its rotations in one undo step. Attachment rotation preserves off-center mounting holes and rigid group offsets. Twist is retained when snapping to another target; free preview orientation persists after a rotation, and starting a new placement resets it. These preview rotations always use circular pointer motion around the projected pivot, including when R starts at the center: moving outward first establishes a radial direction without rotating. `TransformGesture` retains its linear fallback only for ordinary R. Camera gestures and UI hover pause rotation and rebase the pointer to avoid jumps. Placement ignores property shortcuts while rotating. Both paths use the same 15-degree snapping, Snap Bypass, signed wrapping and angle feedback as ordinary R. Placement rules expose `GetRotationAnchor`; ordinary hole placement and Move provide the actual target face, while specialized hardware rules use their aligned axial pivot. Initial placement and Move hold their existing preview and commit through `Placement`, while G/H applies the shared gesture to its existing rigid displacement and MultiPivot. Modal transforms capture unrelated input through settling and the confirmation frame and consume held inputs until release. Multi-selection transforms use the existing MultiPivot directly.

Axis dragging and keyboard transforms share `ObjectDuplicator.CreateCopies`, which clones each part once without cloning a selection pivot and gives copies their own materials. Keyboard transforms read the existing rebindable Duplicate modifier when the operation starts. Copies stay stationary; confirmation records their existence and the selected parts' transforms in one undo step. Cancellation or confirmation without a transform discards temporary copies. Transform and move/pivot `ToolToggle`s opt into `hideDuringKeyboardTransform`; their handle roots deactivate in LateUpdate while G/R captures input, including settling and the confirmation frame, then reactivate according to the retained toolbar selection.

## Transform feedback and part properties

- `InteractionFeedback` owns the bottom-left stack. Independent Grouping Bypass, Snap Bypass and Multi-Select bindings show “Bypassing grouping”, “Bypassing snap” and “Selecting multiple” in one shared textbox, joined in that order with ` · ` when held together. Duplicate shows “Duplicating” in its own box. Messages follow the existing rebindable inputs and modal capture, stack with G/R help, and reserve space above visible footer graphics registered on the scene canvases, including graphics created after startup. `TransformFeedback` uses bundled Roboto and explicit white text on 60%-opaque dark panels for help, measurements and numeric entry; it does not depend on the platform default IMGUI font/skin. Measurement boxes fit their distance/angle text; the shared modifier box fits its active labels, while help wraps at the available width. Fitted widths include a pixel-rounding allowance, and labels that fit stay unwrapped. Canvas graphics must be accessed by index: Unity’s `GraphicRegistry` returns an `IndexedSet` whose enumerator throws `NotImplementedException`. The existing Roboto-Regular font GUID is preserved at its Resources location. Very short windows clip text inside separate, on-screen panels.
- Mouse handle drags and G/R show the operation's snapped target distance in inches or angle in degrees above and to the right of the pointer. `TransformFeedback` scales font sizes, boxes and offsets together against a 1600×900 reference, with a minimum readable size; the G/R help panel also wraps to the available width. G with X/Y/Z draws a red/green/blue world-axis guide through the starting pivot. Set `KeyboardTransformTool.showConstraintAxis` to false on Placement to disable that guide.
- G constrained to X/Y/Z wraps the OS cursor within the camera's visible editing viewport. `TransformCursor` supplies the edge positions; `TransformGesture.RebasePointer` retains unsnapped movement across each wrap for all three axes and free-plane projection, preserving the original grab/numeric anchor and snapping phase. Perspective axes whose targeting plane crosses the viewport use a stable screen projection at the original depth to avoid dead zones. Input System's pointer position updates immediately with the warp so feedback follows the visible cursor. Wrapping stops during rotation, free grab, hole snapping, numeric entry, settling and completion. Measurement/help/numeric panel bounds stay clamped to the screen, including small windows; numeric content clips inside its panel.
- Rotation values wrap by signed full turns relative to the starting pose: `375° → 15°`, `−375° → −15°`, and either full turn returns to `0°`. Keyboard/ring drags retain accumulated pointer motion, including after numeric-entry pauses, so crossing 180° does not flip direction; normalization happens after snapping. Relative numeric entry and shared angle feedback use the same `TransformSnapping.WrapAngle` rule. Global numeric rotation wraps the requested Euler component before computing its existing shortest delta.
- Slash numeric entry is shared by G/R and rotation during initial placement, Move and G/H. `MoveRotation` owns the same `TransformNumericInput` and `TransformFeedback.DrawNumeric` UI for all preview rotations. Slash cycles relative → global → mouse; Enter commits the exact rotation as part of the placement/move, bypassing snapping. Relative values start at the current R gesture. For a snapped attachment, global means total twist in the mating frame, preserving the hole normal and contact; in free rotation it sets the chosen world Euler component just like ordinary R. Typing captures shortcuts, selection, clicks and camera navigation. Invalid entry or closing with slash restores circular mouse control without a jump; Escape cancels the operation.
- For ordinary G/R on an axis, slash cycles relative → global → mouse; unconstrained grab opens global `X, Y, Z` entry immediately. Numbers use decimal points, optional signs and inches/degrees. Relative values measure from the operation's starting pivot/orientation. Global movement sets the pivot's chosen world coordinate; global rotation replaces the selected world Euler component and preserves the other two components of the selection's initial orientation. Multi-selection uses its pivot as the orientation reference.
- Enter with valid numeric input confirms one undoable operation with the exact value, bypassing snapping. Typing pauses manual targeting; third slash or invalid Enter discards the text, rebases the pointer at the existing target and resumes mouse control without a jump. Escape/right-click still cancels the entire operation. `TransformNumericInput` receives text through the Input System, supports negative values, editing and paste, and captures transform shortcuts while typing.
- Selection Preferences rows use distinct 35-unit spacing, and the Preferences panel grows to fit them. `InteractionUpdatesSetup` lays out both existing and newly added shortcuts, including all four property arrows and the three separate modifier rows.
- `HoleData` reads its source collider transform directly. `HoleFace` retains its direction relative to the owning part and refreshes in Update/LateUpdate; handle followers run in LateUpdate. Selecting, moving, rotating and undoing a hole selection retain its live pivot and face orientation.
- Main’s `EventSystem` uses `ToolUIInputModule`, derived from `InputSystemUIInputModule`. It gates UI navigation/submit/cancel at dispatch using the shared `KeyboardTransformTool.BlocksUINavigation` capture, including placement rotation and the confirmation frame. This prevents Enter from activating a focused button before or after a numeric submission. Focused part rows always suppress UI submit/cancel, so Enter cannot toggle placement on/off; pointer part selection still works. Other UI buttons retain normal Enter submission outside tool capture, and text-field updates, pointer clicks and scrolling continue through the base module. The module restores `sendNavigationEvents` after each dispatch and leaves `move` unassigned. Arrow keys therefore do not navigate between part buttons, search and other UI controls; property shortcuts still receive them. Pointer clicks, scrolling, submit/cancel and text-field caret editing remain configured.
- Arrow shortcuts repeat while held, step lists in their displayed order, change numeric hole counts by 1 and other custom numbers by 0.5, and respect limits. Changing the first property normalizes dependent second-property options/limits. Text fields, rebinding, noclip, Connect and active transforms capture input before property shortcuts.
- Placement property changes refresh the preview mesh without restarting placement or resetting its mechanical alignment. P uses the selected part's saved ID to start ordinary repeated placement; it does not duplicate the part or its connected group. All five new shortcuts have Preferences rows and support rebinding.
- Initial placement uses `PartHolePlaceDisplacement` before the free-plane fallback. It reads the live hole collider under the pointer and honors Space for the opposite face. `PartGenerator.TryGetPlacementHole` supplies a primary or nearest local hole; plates and aluminum generators account for generated hole offsets, including even counts. The new part's mating hole face sits exactly on the target face, without grid quantization. Parts with no source hole place their origin at the target face. Attachment data refreshes with preview properties; hardware-specific placement retains priority.
- New parts reset to their own initial orientation when placement starts and when returning to the free plane. `PartData.flipPlacement` turns over specific variants (bevel gears, rack, hand crank, inner slide trunk, fixed-length rails, Vision/Potentiometer sensors, and both motors). Aluminum generators expose their own `flipPlacement` setting: channels and angles turn over, while the generated motion rail retains its original orientation. Fixed-length `RAILS` and generated `RAIL` are distinct part types and require separate coverage. `PartPlacementData` caches the corrected free orientation and mounting face together. Specialized hardware rules apply the same orientation correction.
- `PartData.placementHole` optionally chooses the screw mounting anchor independently of `primaryHole`. Both motors use a threaded mounting hole for initial placement and retain the shaft socket as their primary/mechanical hole and `Motor.shaftHole`; both mounting screws then align with the half-inch structural pattern. The potentiometer likewise uses a screw hole for placement while retaining its central shaft hole. Attachment holes must belong to the chosen variant; the 5.5W motor and high-strength block bearing reference their own geometry, keeping prefab display offsets out of runtime pivots.
- A single selected part exposes its properties in the existing panel. Property edits regenerate the part through its generator, retaining world pose, color and saved state. With a hole selected, the closest remaining local hole stays at the selected hole center. Regeneration rebuilds holes/colliders/detectors and saves the new parameter ID; `ReplacementElement.Load` captures affected detectors before changing existence, synchronizes physics, then re-queries actual capsule/hole overlaps and forms valid fastener groups before restoring selection. This path applies to every part generator, including replacement of a screw or shaft and its own detector. It keeps valid stationary connections through edits and undo/redo for gears, sprockets, wheels, collars, structural parts and threaded targets, while still enforcing occupancy, alignment and clamp bounds. Changes that move/remove mating holes or shorten a fastener out of reach release those connections. `HoleInsert` initializes its visuals from existing occupancy because reconnection can happen before Start. Each change records old/new existence and selection as one undoable operation. These programmatic selection restorations bypass pointer selection conditions (including the UI guard), while ordinary selections retain their existing conditions. Multi-selection property editing is intentionally excluded.
- The legacy `Select Opposite Hole` binding ID remains compatible with saved preferences and is labeled `Opposite Hole Face (Hold)` in Preferences. Space flips the hovered face normal and chooses the other end of that hole, rather than searching for another hole.

## Connect tool contract

- Optional preselection defines the rigid set that will move.
- With no preselection, the source endpoint's body/connected group becomes the moving set.
- The source endpoint must belong to the moving set; the target must be outside it.
- A hole endpoint uses its live hole center. A body endpoint uses the `SavedObject` transform position.
- Multiple selected bodies retain their relative offsets and move through their existing `MultiPivot`.
- Direction/orientation is ignored. Only translation is applied.
- `Escape` exits the tool; completed operations participate in undo/redo.

## Simulation and gear snapping

- `SimulationTool` joins the existing toolbar ToggleGroup. Choose a motor, shaft or spur gear, then move the mouse horizontally to scrub the connected drivetrain. Existing selections can supply the driver. The first version is kinematic: it propagates shaft rotation and signed tooth-count ratios, with no force/contact solver. Motor housings, bearings and structural editing groups stay stationary; collars, sprockets, wheels, lock bars and cranks on a shaft follow it. Incompatible gear loops are rejected.
- `MechanismSimulation` captures world poses and evaluates every frame from that baseline, independently of editing pivots and `GroupManager`. It preserves parenting and includes complete assembly revolution times. `SimulationPart` bakes each spur gear variant's mechanical center, axis, tooth reference, pitch radius and axial extent into the resource prefab; ordinary generation, duplication, regeneration and build loading retain these components. Future drive preferences/presets can build on this metadata and the separate motion graph.
- Manual previews revert on Escape/right-click, focus loss, tool exit or another edit. Click / the explicit Set pose button commits one undo state; animation has Play/Pause, Reset, a speed slider and a seekable timeline with each part's turn duration and loop boundaries. Preview transforms never enter build snapshots: `SceneBuild.ToBuildData` reads baseline poses through `SimulationTool.SavedPose`. Load, placement, deletion and undo/redo restore before changing the build. Detector updates are held during previews and refreshed on commit/cancellation.
- Preferences has a Simulation category. Enable Simulation Tool defaults to 5. Animation, Play/Pause, Reset, Faster, Slower, Commit and Cancel are independently rebindable and have no defaults. UI input, selection and camera ownership follow the simulation mode; playback allows camera navigation, while manual motion captures the camera.
- `GearSnapping` shares pitch-circle alignment and tooth-to-gap phasing across `GearPlaceDisplacement` (initial placement and Move) and keyboard G → H. Hover the circumference/vicinity of a stationary gear to mesh a moving gear with parallel axes and coplanar centers. Existing hole/shaft rules retain priority. Gear G/H selects its mechanical center automatically when no source hole was chosen. Target queries exclude moving parts and reject foreground occlusion. Bevel/worm/rack engagement is outside this first version.

## Important invariants and pitfalls

- Main's `PlatformEvents.OnMacStart`, like `OnWindowsStart`, enables the build manager and file-name control. The manager starts inactive in the serialized scene; its startup must run to install Save and unsaved-change callbacks.
- Recent Builds reads saved path strings without testing disk availability during startup or refresh. Probing offline network/cloud locations synchronously can block the first frame. Availability is checked by the existing background reader only when a file is chosen; unavailable entries remain available for retry. `StartupDiagnostics` emits `[Startup]` milestones to the standard player log so a launch hang can be located before managed startup, graphics initialization, scene startup or the first frame.
- Build Open/Save As and parts-list export use `NativeFileDialogs` and SFB's async API. The SFB macOS plugin documents focus-related failures with synchronous panels. Native callbacks are posted to Unity's synchronization context before updating scenes/UI; callback delegates stay rooted in the macOS wrapper. Only one native panel may be pending, and `BuildsManager` also guards reads/writes against overlapping requests. Snapshot scene data on Unity's thread, serialize/deserialize on a worker, and generate parts/update events back on Unity's thread. Save-before-load/quit proceeds only after a successful write; cancellation or failure retains the current scene/path. Build reads use read-only/shared streams with deterministic disposal and case-insensitive `.pbb` extensions. Panels remember the last build directory; startup scans file arguments after the executable. Recent Builds uses the same reader without a panel.

- Do not add a second parent pivot around an active `MultiPivot`; translate the existing pivot instead.
- `MeshCombiner` gathers visible nested renderers once, excludes hole geometry, and transforms all submeshes into the preview frame without reparenting or moving sources. Both Move and G/H use it, plus `MovePreviewVisibility` to restore original renderer/outline states. Placement owns and releases its generated preview meshes on replacement/destruction. Legacy placement-layer exclusion remains in place for pointer targeting.
- Avoid moving both a parent and its child as separate roots or the child will receive the delta twice.
- Hole colliders live on the `HoleCollisions` layer and reference their owning part through `HoleData.part`.
- Placement-layer preview objects must not be treated as normal selectable targets.
- `Assets/Scenes/Main copy.unity` is not the active production scene.
- Unity-generated `.meta` files must accompany every new asset.
- Preserve unrelated work in the working tree. Build products and `Library` are generated artifacts, not source.

## Validation and build

Run `-executeMethod ProtobotEditorTools.SimulationValidation.Validate` for scene/toolbar, unbound actions, Preferences, gear metadata and placement priority checks. Run `-batchmode -nographics -executeMethod ProtobotEditorTools.SimulationValidation.Smoke` without `-quit` for generated drivetrain and tool interaction checks (ratios, stationary housings/bearings, reversible evaluation, timeline, reset, cancellation, wrapping, commits, undo/redo, preview-safe saves and gear vicinity snapping). `SimulationSetup.Configure` installs the serialized Main-scene integration idempotently. Existing hole/keyboard/fastener suites remain regression checks for shared placement and input paths.

Run a headless compile/import check:

```sh
/Applications/Unity/Hub/Editor/6000.6.6f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -nographics -quit \
  -projectPath /absolute/path/to/Protobot-Rebuilt \
  -logFile /tmp/protobot-compile.log
```

Build the Apple Silicon macOS player as `build.app` (the helper explicitly selects ARM64, refreshes/verifies the app's ad hoc signature after building, and restores the previous architecture setting):

```sh
/Applications/Unity/Hub/Editor/6000.6.6f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -nographics -quit \
  -projectPath /absolute/path/to/Protobot-Rebuilt \
  -buildTarget StandaloneOSX \
  -executeMethod ProtobotEditorTools.MacBuild.BuildAppleSilicon \
  -logFile /tmp/protobot-build.log
```

The build helper runs the following signing/verification steps automatically. For an app built through another route, run them manually (copied Unity libraries can retain invalid signatures after architecture stripping):

```sh
codesign --force --deep --sign - --preserve-metadata=identifier,entitlements,flags,runtime build.app
codesign --verify --deep --strict build.app
```

Build the 64-bit Windows Mono player into `Builds/Windows-Mono/Protobot.exe` (requires Windows Build Support; the helper explicitly selects Mono and restores the previous scripting backend):

```sh
/Applications/Unity/Hub/Editor/6000.6.6f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -nographics -quit \
  -projectPath /absolute/path/to/Protobot-Rebuilt \
  -buildTarget Win64 \
  -executeMethod ProtobotEditorTools.WindowsBuild.BuildMono \
  -logFile /tmp/protobot-windows-mono-build.log
```
