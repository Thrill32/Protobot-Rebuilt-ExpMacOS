# Protobot Rebuilt Context Map

This is the quick orientation document for both human contributors and coding agents. It describes the current repository rather than the historical release documented in parts of the README.

For the complete add-part flow, catalog/generator authoring, placement rules, imported/copied sets and persistence contracts, read [Adding parts in Protobot](ADDING_PARTS.md).

## Project at a glance

- Unity editor: `6000.6.6f1` (see `ProjectSettings/ProjectVersion.txt`).
- Active scene: `Assets/Scenes/Main.unity`.
- Rendering: Universal Render Pipeline (URP). The main 3D camera is the Base camera; `UICamera` is stacked as an Overlay camera.
- Primary macOS development build: `build.app`.
- Source namespace is mostly `Protobot`; older scripts in the project may still use the global namespace.

The standalone CLI supports `init --data-dir <new-dir> --room <id> --catalog <manifest>` or `--snapshot <RoomExport>`, with a password file or hidden prompt. `SetupCommands.cs` validates and privately stages a new SQLite room plus a separate owner capability before publishing the directory. No runtime/catalog change is needed to select a different port.

## Core interaction flow

1. `MouseCast` resolves the collider under the pointer.
2. A selector creates an `ISelection` and sends it to `SelectionManager`.
3. Selection responses update outlines, object links, tool availability, and state behavior.
4. A movement tool operates on the selected object or `MultiPivot`.
5. `ObjectElement` snapshots provide undo/redo state around the mutation.

The Connect tool is slightly different: it freezes the body set when activated, captures a source hole/body pivot and a target hole/body pivot, then applies the same translation delta to the independent movement roots. It intentionally does not rotate parts.

With Move/pivot (`2`) active, a single hole click selects its face and immediately starts the existing Move placement preview. `ClickSelector` starts `MoveToolManager` after selection responses finish, preserving the clicked face and Grouping Bypass scope. Body clicks still select normally. Placement ignores confirmation input on its starting frame and waits for the Place binding to be released on a later frame before accepting a fresh press. Focus changes reset this guard, so a held or delayed click from a native file picker cannot immediately commit an imported build; the next click places it.

Color painting resolves deep child colliders and holes to their owning `SavedObject`, then paints the selected bodies with their latched Grouping Bypass scope. `PartColors` covers all body mesh material slots, including nested wheel/motor geometry, without a metallic-value restriction; hole/mount markers are excluded. It preserves shaders, textures and each material's alpha, and uses owned runtime materials to keep source/catalog instances independent. One paint action creates one `ColorElement` state for the full affected set; undo restores exact original slot colors and redo restores the painted result. The Default palette option restores each body renderer/material slot's generated RGBA color and clears whole-body paint metadata, rather than applying a white tint. `PartGenerator.SetId` and `CustomModel.Create` capture that palette in `OwnedPartMaterials`; serialized renderer/slot references retain it through runtime duplication. Reset parts use the new variant's defaults on parameter changes. Legacy RGB load/regeneration preserves the generated alpha. Palette initialization reapplies the selected mode after slider callbacks so they cannot replace the Default brush. Painting an unchanged color or resetting an already-default part adds no paint state. Hole and box selectors only dispatch selection; they do not paint separately. `SelectionManager` captures whether dispatch began with a selector before state recording clears that reference, so programmatic selection restoration never paints. The eyedropper shares body/material resolution. Optional `ObjectData.hasPaint` distinguishes whole-body tinting from legacy first-material colors, preserving paint through file/clipboard transfers, duplication and parameter regeneration. `BuildData.HasColors` shares version detection between loading and dirty-state comparison, so resetting RGB in older colored builds is saved while pre-color builds remain clean on load. Temporarily hidden source renderers still supply their saved colors.

Escape unwinds one level per press. Native dialogs and rebinding own their cancellation; focused text/dropdowns, menu popups and Preferences close before scene editing. Next, cancel an active G/R or numeric transform, placement/Move/copy preview, gizmo drag, selection box, custom-model mode, simulation preview or pending Connect source/motion. Movement cancellation restores starting poses and removes temporary Alt copies/undo elements while retaining selection and toolbar mode. With no pending action, Escape clears the primary selection (including multi/hole selections) even over UI or under Connect/Simulation selection guards. The following press turns off the current toolbar tool. Connect resets its captured source/body set when selection clears; simulation remains enabled after preview cancellation and deselection. Held Escape cannot advance tiers. `EscapeDeselect` runs before ordinary Updates, consumes conflicting `InputEvent`s and UI cancel navigation, and requires release before another tier. Physical Escape stays universal even if Stop Placing is rebound; its other binding retains ordinary placement-stop behavior. Escape placement cancellation is synchronous through `Placement.CancelPlacement`.

Bindings are rebindable in Preferences. While noclip mode is active, its movement keys are captured so unrelated bindings do not also fire.

`ShortcutPriority` gives complete Command/Control/Option/Shift chords priority over bindings on the same trigger key with fewer modifiers, for both default composites and user-rebound chords. Only complete alternatives contribute specificity; an inactive alternative cannot shield a simpler binding. Modifier-only bindings remain available. `InputEvent` snapshots chord priority per input update/frame before dispatch, so order cannot let a single-key handler fire first; a consumed trigger stays suppressed until release, including when the modifier is released first. Disabled actions do not reserve keys. Rebinding retains all four modifier families; the original trigger binding ID stays in slot 3 so existing preferences still load. Existing modal-axis, Escape and noclip capture still apply.

During G/R, physical X/Y/Z take priority over every conflicting binding, including rebound Grab, Rotate, grid, Duplicate, Snap Bypass and Grouping Bypass actions. Held conflicting actions stay suppressed until release. `Grab Hole Snap` is a separate rebindable input (default H), with a Preferences row; during grab it consumes conflicting inputs before their handlers run, including grid visibility. It is inactive during rotation and ordinary selection.

G → H is a shortcut into tool 2 Move. `KeyboardTransformTool.MoveFromGrab` cancels the uncommitted grab, restores its starting transforms and discards temporary Alt copies, then activates the authored Move toolbar toggle and calls `MoveToolManager.StartMoving` with the unchanged selection and latched Grouping Bypass scope. The same `GameObjectPlacementData`, `Placement`, displacement rules, render visibility, rotation, commit and cancellation paths serve both entry points. Single bodies and multi-selections use their normal Move frame; a selected hole uses its exact face. The handoff adds no undo state and captures its input frame so H cannot also toggle the grid or place the preview. It retains the saved `Grab Hole Snap` binding ID, shown as “Move Tool During Grab” in Preferences. There is no separate G/H source picker, targeting loop or preview. H again, XYZ and slash follow ordinary Move behavior rather than returning to the discarded grab.

Automatic groups use symmetric live graph edges. A screw connects parts between its head and its furthest threaded hole. A shaft needs two distinct clamp bodies and includes only holes between the outermost clamps. Detector additions/removals are idempotent and enforce ownership; perpendicular holes cannot attach. Hole intersection checks also compare projected axial interiors so rotated, thick bores with real shaft clearance are not rejected merely because their world-aligned bounding boxes overlap. Every hole change refreshes the fastener graph after the frame, replacing previous membership even when counts match. Disabling/deleting holes, detectors or fasteners releases occupancy and connections; re-enabled geometry is detected again by physics. Graph traversal excludes inactive/deleted parts and resets at runtime startup.

`ISelection.individual` records the independent Grouping Bypass modifier when pointer selection occurs and follows hole selections, multi-selection membership, undo/redo and property regeneration. Selection links carry this scope to keyboard transforms, handle movement, duplication, Connect, outlines and move-tool previews; releasing the modifier does not silently re-expand the assembly.

Grab and rotation use the shared 0.5-unit / 15-degree snapping and Snap Bypass binding. Both ease toward their targets over 0.25 seconds with DOTween's standard easing, matching axis dragging. Confirmation lets the easing finish before capturing the exact final transform for undo; cancellation kills the tween and restores the starting pose. The shared rigid displacement is interpolated so multi-selection spacing stays fixed during rotation. Rotation starts on the nearest primary world axis (largest absolute camera-forward component), captured when R is pressed; it never rotates about an arbitrary camera axis. Initial placement, Move and G/H share `MoveRotation` and the existing `Rotate Placement` binding ID, labeled `Rotate Selection / Placement` in Preferences. R enters rotation about the chosen hole/screw axis and mating point, or the nearest camera-facing world axis through the current preview pivot when no target is locked. The target stays locked while the pointer rotates; R again resumes positioning, retaining the rotation. Click commits the placement/move, and Escape cancels. After G → H, only the subsequent Move commit creates an undo step; the discarded grab adds none. Attachment rotation preserves off-center mounting holes and rigid group offsets. Twist is retained when snapping to another target; free preview orientation persists after a rotation, and starting a new placement resets it. These preview rotations always use circular pointer motion around the projected pivot, including when R starts at the center: moving outward first establishes a radial direction without rotating. `TransformGesture` retains its linear fallback only for ordinary R. Camera gestures and UI hover pause rotation and rebase the pointer to avoid jumps. Placement ignores property shortcuts while rotating. Both paths use the same 15-degree snapping, Snap Bypass, signed wrapping and angle feedback as ordinary R. Placement rules expose `GetRotationAnchor`; ordinary hole placement and Move provide the actual target face, while specialized hardware rules use their aligned axial pivot. Initial placement and Move, including G → H, hold their preview and commit through `Placement`. Modal transforms capture unrelated input through settling and the confirmation frame and consume held inputs until release. Multi-selection transforms use the existing MultiPivot directly.

Axis dragging and keyboard transforms share `ObjectDuplicator.CreateCopies`, which clones each part once without cloning a selection pivot and gives copies their own materials. Keyboard transforms read the existing rebindable Duplicate modifier when the operation starts. Copies stay stationary; confirmation records their existence and the selected parts' transforms in one undo step. Cancellation or confirmation without a transform discards temporary copies. Transform and move/pivot `ToolToggle`s opt into `hideDuringKeyboardTransform`; their handle roots deactivate in LateUpdate while G/R captures input, including settling and the confirmation frame, then reactivate according to the retained toolbar selection.

## Transform feedback and part properties

- `InteractionFeedback` owns the bottom-left stack. Independent Grouping Bypass, Snap Bypass and Multi-Select bindings show “Bypassing grouping”, “Bypassing snap” and “Selecting multiple” in one shared textbox, joined in that order with ` · ` when held together. Duplicate shows “Duplicating” in its own box. Messages follow the existing rebindable inputs and modal capture, stack with G/R help, and reserve space above visible footer graphics registered on the scene canvases, including graphics created after startup. `TransformFeedback` uses bundled Roboto and explicit white text on 60%-opaque dark panels for help, measurements and numeric entry; it does not depend on the platform default IMGUI font/skin. Measurement boxes fit their distance/angle text; the shared modifier box fits its active labels, while help wraps at the available width. Fitted widths include a pixel-rounding allowance, and labels that fit stay unwrapped. Canvas graphics must be accessed by index: Unity’s `GraphicRegistry` returns an `IndexedSet` whose enumerator throws `NotImplementedException`. The existing Roboto-Regular font GUID is preserved at its Resources location. Very short windows clip text inside separate, on-screen panels.
- Mouse handle drags and G/R show the operation's snapped target distance in inches or angle in degrees above and to the right of the pointer. `TransformFeedback` scales font sizes, boxes and offsets together against a 1600×900 reference, with a minimum readable size; the G/R help panel also wraps to the available width. G with X/Y/Z draws a red/green/blue world-axis guide through the starting pivot. Set `KeyboardTransformTool.showConstraintAxis` to false on Placement to disable that guide.
- G constrained to X/Y/Z wraps the OS cursor within the camera's visible editing viewport. `TransformCursor` supplies the edge positions; `TransformGesture.RebasePointer` retains unsnapped movement across each wrap for all three axes and free-plane projection, preserving the original grab/numeric anchor and snapping phase. Every constrained axis uses a stable screen projection at the original depth: equal pixel travel produces equal world movement before/after wrapping, including oblique perspective views and end-on axes. Free grab retains its camera-plane ray projection. Wrapping stops during rotation, free grab, Move placement, numeric entry, settling and completion. Measurement/help/numeric panel bounds stay clamped to the screen, including small windows; numeric content clips inside its panel.
- Both axis wrapping and horizontal simulation scrubbing call `CursorWarp.Warp`, rather than issuing separate raw OS warps. It updates Input System position immediately and clears the teleport delta. A short, device-scoped `onEvent` guard rewrites stale/pre-acknowledgement edge coordinates and duplicate native acknowledgements; coalesced acknowledgements retain real post-warp motion. Corrected deltas continue to accumulate within an input update. Button/wheel fields remain intact, and locked noclip input is excluded. Horizontal scrubbing tests only horizontal edges, so reaching a top/bottom edge cannot issue repeated zero-distance warps. Preserve this handoff when adding another infinite-drag consumer; `WarpCursorPosition` alone completes asynchronously.
- Rotation values wrap by signed full turns relative to the starting pose: `375° → 15°`, `−375° → −15°`, and either full turn returns to `0°`. Keyboard/ring drags retain accumulated pointer motion, including after numeric-entry pauses, so crossing 180° does not flip direction; normalization happens after snapping. Relative numeric entry and shared angle feedback use the same `TransformSnapping.WrapAngle` rule. Global numeric rotation wraps the requested Euler component before computing its existing shortest delta.
- Slash numeric entry is shared by G/R and rotation during initial placement, Move and G/H. `MoveRotation` owns the same `TransformNumericInput` and `TransformFeedback.DrawNumeric` UI for all preview rotations. Slash cycles relative → global → mouse; Enter commits the exact rotation as part of the placement/move, bypassing snapping. Relative values start at the current R gesture. For a snapped attachment, global means total twist in the mating frame, preserving the hole normal and contact; in free rotation it sets the chosen world Euler component just like ordinary R. Typing captures shortcuts, selection, clicks and camera navigation. Invalid entry or closing with slash restores circular mouse control without a jump; Escape cancels the operation.
- Numeric entry uses the bundled font's ASCII `|` caret; the box-drawing caret requires a fallback font and can stall its first repaint. `InteractionFeedback` prepares the label/field glyphs at startup, after a screen-scale change or after the font atlas rebuilds, keeping dynamic-font preparation out of the slash handler and opening repaint.
- For ordinary G/R on an axis, slash cycles relative → global → mouse; unconstrained grab opens global `X, Y, Z` entry immediately. Numbers use decimal points, optional signs and inches/degrees. Relative values measure from the operation's starting pivot/orientation. Global movement sets the pivot's chosen world coordinate; global rotation replaces the selected world Euler component and preserves the other two components of the selection's initial orientation. Multi-selection uses its pivot as the orientation reference.
- Enter with valid numeric input confirms one undoable operation with the exact value, bypassing snapping. Typing pauses manual targeting; third slash or invalid Enter discards the text, rebases the pointer at the existing target and resumes mouse control without a jump. Escape/right-click still cancels the entire operation. `TransformNumericInput` receives text through the Input System, supports negative values, editing and paste, and captures transform shortcuts while typing.

- `HoleData` reads its source collider transform directly. `HoleFace` retains its direction relative to the owning part and refreshes in Update/LateUpdate; handle followers run in LateUpdate. Selecting, moving, rotating and undoing a hole selection retain its live pivot and face orientation.
- Main’s `EventSystem` uses `ToolUIInputModule`, derived from `InputSystemUIInputModule`. It gates UI navigation/submit/cancel at dispatch using the shared `KeyboardTransformTool.BlocksUINavigation` capture, including placement rotation and the confirmation frame. This prevents Enter from activating a focused button before or after a numeric submission. Focused part rows always suppress UI submit/cancel, so Enter cannot toggle placement on/off; pointer part selection still works. Other UI buttons retain normal Enter submission outside tool capture, and text-field updates, pointer clicks and scrolling continue through the base module. The module restores `sendNavigationEvents` after each dispatch and leaves `move` unassigned. Arrow keys therefore do not navigate between part buttons, search and other UI controls; property shortcuts still receive them. Pointer clicks, scrolling, submit/cancel and text-field caret editing remain configured.
- Arrow shortcuts repeat while held, step lists in their displayed order, change numeric hole counts by 1 and other custom numbers by 0.5, and respect limits. Changing the first property normalizes dependent second-property options/limits. Text fields, rebinding, noclip, Connect and active transforms capture input before property shortcuts.
- Catalog placement property changes refresh the preview mesh without restarting placement or resetting its mechanical alignment. P captures the current selection's exact geometry, colors, custom mounting points, relative positions and rotations, honoring the latched Grouping Bypass scope. `SelectionPlacementData` owns inactive templates outside the live build and a combined read-only preview; it never clones or reparents a source MultiPivot. Click creates one independent set at the preview pose in a single undo step and retains repeated placement. Escape, replacement or disable releases the templates and preview without creating parts. Templates freeze mutable materials, including custom-model resources, and remain valid if originals change or disappear. Source transform/move handles hide and reject pointer drags during P placement. Property controls remain for catalog placement and existing single-part edits, while P uses its frozen geometry. The existing `Pick Part` binding ID is retained and labeled `Copy Selected Parts` in Preferences.
- P with a `HoleSelection` uses that exact live face as the copy frame. Ctrl-clicking a hole after body/multi-selection retains a body-relative `SelectedHoleAnchor` on `MultiSelection`, shows the chosen face, and includes its body without nesting old pivots. P aligns the duplicate of that face to hovered holes or screw endpoints through the shared `HolePlaceDisplacement`/`MoveTargeting` path, including opposite target faces and attachment rotation. A body click clears the multi-selection's hole anchor. With no source hole, P bypasses every hardware, ordinary-hole and gear snapping rule and uses only the normal plane/grid, Snap Bypass and free R rotation. Arrow shortcuts and P retain their existing rebindable inputs.
- Import/paste shares `SelectionPlacementData.FromBuild`, using inactive, owned templates; no temporary parts or chains enter build snapshots. A click creates one set, stops placement, selects exactly the new bodies with individual scope, and records geometry, chain existence and before/after selection in one undo state. Placement and undo/redo restore these selection snapshots through `SelectionManager.SetCurrent` with `bypassResponseSelectors`, so held Control/Snap Bypass cannot merge a single-part result with the previous selection. Escape/replacement/disable discards the preview. Regular project files center the preview on visible geometry; selection exports and clipboard payloads retain their optional `BuildData.placementAnchor`, including an explicitly selected source-hole face. Existing project geometry, view and save path remain unchanged. Loading another project cancels pending transfers/previews and clears stale selections; already captured copy data can finish after switching projects.
- Selection snapshots and P/transfer copies retain only chains whose endpoints are all included. Inactive templates preserve the original connection IDs as a mapping; every placed copy gets fresh runtime IDs and remaps its chains to that set. Custom geometry, mounting points, colors, parameters and saved part state remain embedded. Selection export captures the chosen set before opening its panel and never invokes the whole-project `OnSaveBuild` event. Its directory preference is separate from the current build directory.
- The “Placing … parts” status belongs to `Placement.ControlsText`, alongside the live rotation/confirmation hints. It persists while the copy/import preview is active and clears immediately on placement/cancellation; repeated P stamps retain it until placement ends. Do not emit this in-progress status through the four-second `InteractionFeedback.Notify` toast.
- `OwnedPartMaterials` records private runtime materials for ordinary copied, loaded and painted parts. `ObjectDuplicator` explicitly clones renderer materials; build/clipboard templates and painting instance every renderer slot, including nested wheel tires/rollers, before assuming ownership. Discard/destruction releases only recorded materials, never arbitrary `sharedMaterials` from prefab resources. Ownership references are not serialized into further clones. Custom models retain their own geometry/material cleanup and immutable shared mounting-ring material. Shared textures and shaders are never released by copy cleanup.
- `BuildTransferTool` uses a versioned JSON payload in `GUIUtility.systemCopyBuffer` (96 MB text limit), containing only portable build fields. JSON work and file I/O run off Unity's thread; scene/UI work returns to it. Clipboard text survives build changes and can cross app instances. Ordinary text and malformed payloads do not alter the scene. Copy/paste use complete left/right Command composites and have rows in Preferences → Files / Clipboard; Save Selected Parts As and Import Build are separately rebindable and initially unbound. `InputEvent` gives complete clipboard chords priority over conflicting letter actions, including the C chain action, and suppresses held keys until release. Composite defaults evaluate their own complete chord while legacy rebound chords retain their all-controls requirement. Rebinding now includes Command modifiers, and composite defaults show in Preferences.
- Initial placement uses `PartHolePlaceDisplacement` before the free-plane fallback. It reads the live hole collider under the pointer and honors Space for the opposite face. `PartGenerator.TryGetPlacementHole` supplies a primary or nearest local hole; plates and aluminum generators account for generated hole offsets, including even counts. The new part's mating hole face sits exactly on the target face, without grid quantization. Parts with no source hole place their origin at the target face. Attachment data refreshes with preview properties; hardware-specific placement retains priority.
- All `NUT` variants seat on the positive-Z bearing face of their bore. `PartPlacementData` reverses only their attachment frame; their free starting pose and dedicated screw placement retain their existing orientation and screw endpoint. `ShaftAxisPlaceDisplacement` reverses bare-shaft nut orientation and uses the same bearing-face alignment against nearby holes on either side, including Space for the opposite face. Other shaft hardware keeps its centered-part offsets and orientation. `HolePlacementValidation.Smoke` includes all four nut variants through actual preview/commit paths on holes, screws and shafts via `NutPlacementValidation`.

Fixed-length `RAILS` and generated `RAIL` are distinct part types and require separate coverage. `PartPlacementData` caches the corrected free orientation and mounting face together. Specialized hardware rules apply the same orientation correction.
- `PartData.placementHole` optionally chooses the screw mounting anchor independently of `primaryHole`. Both motors use a threaded mounting hole for initial placement and retain the shaft socket as their primary/mechanical hole and `Motor.shaftHole`; both mounting screws then align with the half-inch structural pattern. The potentiometer likewise uses a screw hole for placement while retaining its central shaft hole. Attachment holes must belong to the chosen variant; the 5.5W motor and high-strength block bearing reference their own geometry, keeping prefab display offsets out of runtime pivots.
- Hex nut retainers (`HexNR`, all three variants) use their central mounting hole with `flipPlacement` so the nut pocket faces away from the mounting surface. Catalog flat bearings (`BRNG`, all variants) use the shared `PartHolePlaceDisplacement.Align` geometry for both hole targets and screw-stack endpoints, including offset bore centers and the actual bore depth. Their rotation anchor is the contact face; the existing centered-hardware path remains for other standoff-rule callers.
- A single selected part exposes its properties in the existing panel. Property edits regenerate the part through its generator, retaining world pose, color and saved state. With a hole selected, the closest remaining local hole stays at the selected hole center. Regeneration rebuilds holes/colliders/detectors and saves the new parameter ID; `ReplacementElement.Load` captures affected detectors before changing existence, synchronizes physics, then re-queries actual capsule/hole overlaps and forms valid fastener groups before restoring selection. This path applies to every part generator, including replacement of a screw or shaft and its own detector. It keeps valid stationary connections through edits and undo/redo for gears, sprockets, wheels, collars, structural parts and threaded targets, while still enforcing occupancy, alignment and clamp bounds. Changes that move/remove mating holes or shorten a fastener out of reach release those connections. `HoleInsert` initializes its visuals from existing occupancy because reconnection can happen before Start. Each change records old/new existence and selection as one undoable operation. These programmatic selection restorations bypass pointer selection conditions (including the UI guard), while ordinary selections retain their existing conditions. Multi-selection property editing is intentionally excluded.
- The legacy `Select Opposite Hole` binding ID remains compatible with saved preferences and is labeled `Opposite Hole Face (Hold)` in Preferences. Space follows the bore axis through touching, coaxial holes and chooses the last outside face, including from oblique views. Free gaps, misalignment, disabled/deleted holes and moving preview geometry cannot extend the stack. `MoveTargeting.ForHole` supplies the shared result for hover markers, hardware/catalog placement, Move, including G → H. Ordinary Move selection determines the source face. Single-click Move uses the resolved face even when it belongs to a later part in the stack.

## Connect tool contract

- Optional preselection defines the rigid set that will move.
- With no preselection, the source endpoint's body/connected group becomes the moving set.
- The source endpoint must belong to the moving set; the target must be outside it.
- A hole endpoint uses its live hole center. A body endpoint uses the `SavedObject` transform position.
- Multiple selected bodies retain their relative offsets and move through their existing `MultiPivot`.
- Direction/orientation is ignored. Only translation is applied.
- `Escape` first cancels a picked source or pending movement, then clears selection, then exits the tool on separate presses; completed operations participate in undo/redo.

## Simulation and gear snapping

- `SimulationTool` joins the existing toolbar ToggleGroup. Choose a motor, shaft, gear, sprocket, rack or keyed attachment, then move the mouse horizontally to scrub the connected mechanism. Existing selections can supply the driver. The system is kinematic: spur/bevel gears transfer signed tooth-count ratios, a single-start worm drives its 24-tooth wheel, racks convert pinion rotation to translation, and explicit chains drive sprockets in the same direction. It does not solve forces or worm self-locking. Incompatible closed gear loops are rejected.
- `MechanismSimulation` refreshes real fastener overlaps and builds rigid sets from screws and keyed shaft/hub connections. It does not weld the broad shaft editing group. Lock bars/collars carry their bolted platforms, screws, nuts and other attached geometry about the driving shaft's axis; bearing bores remain rotary joints and motor output drives are separate from the housing. Every rigid member receives the same baseline-derived displacement, preserving off-center geometry, parenting, undo and cancellation. Motion transfer between rigid sets requires compatible joint axes.
- `SimulationPart.kind` distinguishes spur, bevel, worm, worm wheel, sprocket, rack and keyed attachment geometry. Resource metadata includes the owned mechanical hole, axis, tooth reference, contact plane, pitch radius and chain pitch. Owned-hole fallback prevents one collar variant from using another variant's prefab offset. `MechanismSetup.ConfigureParts` covers mechanisms, sprockets, lock bars, collars, wheels, cams and cranks; ordinary generation/regeneration and build loading retain these components. Linear tracks show travel speed and a time window rather than claiming a repeating turn cycle.
- Manual previews revert on Escape/right-click, focus loss, tool exit or another edit. Click / the explicit Set pose button commits one undo state; animation has Play/Pause, Reset, a speed slider and a seekable timeline with each part's turn duration and loop boundaries. Preview transforms never enter build snapshots: `SceneBuild.ToBuildData` reads baseline poses through `SimulationTool.SavedPose`. Load, placement, deletion and undo/redo restore before changing the build. Detector updates are held during previews and refreshed on commit/cancellation.
- Rotating drivers share the G/R slash numeric editor and feedback: slash cycles relative → global → mouse, Enter commits one exact undoable mechanism pose, and Escape/right-click reverts. Relative degrees refer to the preview baseline and retain complete turns because output gears can have different phases after one input revolution. Global degrees set the nearest world-referenced axial phase, preserving accumulated gear cycles. Zero uses world +Y projected onto the drive plane, or +Z near a vertical axis; the numeric UI names that reference. The driver's mechanical axis stays fixed, as with attachment rotation. Motor angles use the connected shaft's initial phase and leave the housing stationary. Entry pauses playback and captures shortcuts, panel controls, camera and selection. Invalid Enter or third slash discards text and rebases mouse control without a jump; focus loss closes the text subscription and restores all bodies. Racks remain linear drivers; choose their pinion for angular entry. The status line shows relative and global driver angles.
- Preferences has a Simulation category. Enable Simulation Tool defaults to 5 and Chain Selected Sprockets to C. Animation, Play/Pause, Reset, Faster, Slower, Commit and Cancel are independently rebindable and have no defaults. Chain creation/removal is undoable, ignores text editing/modal transforms and reports its result through `InteractionFeedback`. UI input, selection and camera ownership follow the simulation mode; playback allows camera navigation, while manual motion captures the camera.
- `GearSnapping` shares typed engagement/contact geometry across initial placement, Move, G → H and the simulation graph. Spur gears keep parallel axes and exact virtual half-inch lattice centers; no physical hole is required. The lattice follows a coaxial mounting frame or stable world-axis projection and does not spin with the teeth. Bevel gears and worm/wheel pairs align at 90 degrees with their authored contact offsets; their default approach directions follow the virtual pattern while preserving intrinsic mounting dimensions. Rack/pinion snapping aligns the tooth face and travel direction. Snap Bypass allows continuous approaches. Hole/shaft rules retain priority, moving parts are excluded and foreground geometry blocks hidden targets.
- `ChainLoop` stores a logical set of persistent `SavedObject.ConnectionId` values and draws a segmented rope contour around two or more coplanar sprockets of the same chain size. Visual tangent runs and rounded wraps use measured tooth-tip radii plus ribbon/chord clearance, while mechanical transmission retains pitch radii and tooth-count ratios. Straight runs are subdivided at wrap resolution to prevent the line renderer folding short arc edges inward. `SimulationPart.ToothTipRadius` caches its measurement per generated mesh. Multi-sprocket selections must form an unambiguous outer loop; inner/idler routing can be connected in pairs. Chain texture travel follows simulation motion. Missing/deleted endpoints hide and disable transmission until restored; no dangling links are exported. `ObjectData.connectionId` and `BuildData.chains` are optional serialized fields for old build compatibility. Replacement parts retain their identity, while ordinary clones get new runtime identities. Save/load restores chains after parts are created; `BuildData.CompareData` includes the chain topology.

## Important invariants and pitfalls

- Custom model imports parse off the Unity thread and use `NativeFileDialogs.OpenModelAsync`; Unity meshes, colliders and UI are created on the main thread. File limits are 64 MB, 500,000 triangles and 1,500,000 vertices. OBJ supports slash/negative indices and concave planar polygon triangulation; STL supports ASCII and binary (including binary headers beginning with `solid`). Geometry is centered and converted to inches at import, with scale-one instance transforms. External OBJ materials/textures are omitted; the ordinary color tool edits the model's material.
- `ObjectData.customModel` is optional for old build compatibility and embeds immutable primitive mesh arrays plus an independent per-instance mounting-point snapshot. Loading validates custom geometry before removing the current build and creates custom bodies before fasteners. No source-file path or runtime part-type registry entry is needed. Duplicates own their meshes/materials and mounting-point state. The runtime materials live under `Assets/Resources/Custom Models` so player builds retain their shaders.
- Custom mounting points are direct children of their model on `HoleCollisions`, with normal `HoleCollider` ownership and threaded/through behavior. New points default to 0.169-inch diameter and 0.046-inch depth; existing saved dimensions are retained. Their collider overhang permits picking over the uncut model surface; `HoleData.depth` retains the exact configured depth for mating faces. They annotate attachment locations without cutting the imported mesh. Their permanent face rings render only in M/hole-editing mode; mode changes and point creation/enable refresh `Renderer.forceRenderingOff`, keeping attachment colliders and snapping available outside M. Their undo element preserves the hole layer and refreshes nearby fastener occupancy/graphs on addition, deletion and restoration. Delete on a selected custom `HoleFace` removes the point; ordinary holes retain whole-part deletion. Inactive points are excluded from saves. Import/options capture editing input; repeated mounting mode allows orbit/pan/noclip and blocks selection/transforms until M/Escape. Starting placement, Connect, Simulation or loading a build ends this mode.
- `CustomMountGrid` anchors each model plane to its first active coplanar mounting point. N (Recalibrate Mounting Grid) in M mode promotes the last-selected point to the reference for its plane, using its position and roll without moving any points. The operation records sibling order for undo/redo; snapshots and whole-model copies preserve that order so the reference survives reload without a format change. Other planes/models keep their references, and no selection, text entry and pending transforms block the command. The first point is free; subsequent surface placements use a 0.25-inch square layout in that frame, with Snap Bypass allowing arbitrary spacing. The initial frame follows projected model axes, retains its roll in later points, and follows model movement/rotation and file reload. Different models, parallel faces at other depths and differently oriented surfaces have independent layouts. A snapped point beyond the model mesh bounds requires Snap Bypass, which returns placement to the actual clicked surface. Preview-only copies never become grid references.
- Within M mode, `CustomMountEditor` owns highlighted single/multiple point selection. Select Multiple (default Ctrl) toggles ring membership; ordinary clicks select one point. `CustomMountPoint.Pick` includes both faces and hollow centers while respecting foreground occlusion. G/R/Delete reuse their existing bindings. The existing Undo/Redo inputs remain available in M mode with or without selected points after an edit is committed; pending G/R previews and numeric/dimension text entry continue to capture them. G crosses empty imported holes in the last-selected point's plane; axis constraints, quarter-inch movement, Snap Bypass, cursor wrapping and slash entry remain available. R rotates a group about its center, or a single point about its own mounting face. The configured Duplicate hold, latched when G/R starts, moves copies while originals stay fixed. Preview copies have disabled attachment colliders and are excluded from model snapshots; confirmation enables them and records one group undo state, while Escape destroys them and restores the original point selection. Matching existing points are reused during pattern duplication; only new points are selected/recorded. All-overlapping patterns and conflicts in diameter, depth or thread type stay uncommitted. Existing-point previews save their captured local baselines. Group deletion is one undo step. Active point edits retain pointer motion over UI and at or beyond the screen edges so the top toolbar cannot stop axis/depth wrapping. UI clicks do not confirm an edit; Enter still can. Idle point placement continues to pause over UI/outside the screen, while camera gestures and focused text fields pause/rebase edits. Escape cancels an edit, clears point selection, then leaves M on separate presses. Local poses, ownership/layers, dimensions and threaded flags survive copying and persistence, and committed edits/undo refresh fastener occupancy. New-point dimensions/type remain separate from pose editing.
- B (Change Mounting Depth) reuses `TransformGesture`, `TransformNumericInput`, `TransformFeedback`, `TransformCursor` and `CursorWarp`: mouse depth follows the last-selected hole's inward normal, wraps continuously, snaps the shared depth delta to 0.01 inch, and supports Snap Bypass. It keeps each mounting face fixed and extends its back face/collider/ring along that hole's own normal. Group depth differences are preserved, including at the positive/100-inch limits; exact relative numeric input adds a delta to each original depth, while explicit absolute input sets every selected depth to the entered value. Invalid entry resumes the current preview without a jump. During B, the rebindable N grid action instead confirms the depth and copies the last-selected hole's live depth and diameter into New depth/New diameter, leaving thread type and grid order intact. Each depth edit is one undo state; preview saves retain captured centers and depths, and commit/cancel/undo refresh attachment geometry and fastener occupancy.

- Main's `PlatformEvents.OnMacStart`, like `OnWindowsStart`, enables the build manager and file-name control. The manager starts inactive in the serialized scene; its startup must run to install Save and unsaved-change callbacks.
- Recent Builds reads saved path strings without testing disk availability during startup or refresh. Probing offline network/cloud locations synchronously can block the first frame. Availability is checked by the existing background reader only when a file is chosen; unavailable entries remain available for retry. `StartupDiagnostics` emits `[Startup]` milestones to the standard player log so a launch hang can be located before managed startup, graphics initialization, scene startup or the first frame.
- Build Open/Save As, model/build import and parts-list export use `NativeFileDialogs` and SFB's async API. The macOS bridge is maintained in `Native/StandaloneFileBrowserMac`: it prepares cached Open/Save panels after interactive scene startup, copies request arguments before queueing AppKit work onto its main thread, and presents asynchronous sheets (or a modeless panel without an owner) instead of entering a nested `runModal` loop. Common single-group filters need no custom accessory; panels, filter controls and unchanged directory URLs are reused. Empty directory strings retain the panel location. `allowedContentTypes` uses an empty array for unrestricted browsing. Startup preparation skips batch-mode checks. The macOS Editor selects its native backend independently of the player build target; Windows/Linux players retain their own backends. Native callbacks are posted to Unity's synchronization context before updating scenes/UI; callback delegates stay rooted in the macOS wrapper. Quit, Play Mode exit and assembly reload invalidate queued/active native callbacks and cancel visible sheets before the managed domain can unload. Only one native panel may be pending, and `BuildsManager` also guards reads/writes against overlapping requests. Snapshot scene data on Unity's thread, serialize/deserialize on a worker, and generate parts/update events back on Unity's thread. Save-before-load/quit proceeds only after a successful write; cancellation or failure retains the current scene/path. Build reads use read-only/shared streams with deterministic disposal and case-insensitive `.pbb` extensions. Panels remember the last build directory; startup scans file arguments after the executable. Recent Builds uses the same reader without a panel.

- Do not add a second parent pivot around an active `MultiPivot`; translate the existing pivot instead.
- `MeshCombiner` gathers visible nested renderers once, excludes hole geometry, and transforms all submeshes into the preview frame without reparenting or moving sources. Both Move and G/H use it, plus `MovePreviewVisibility` to restore original renderer/outline states. Placement owns and releases its generated preview meshes on replacement/destruction. Legacy placement-layer exclusion remains in place for pointer targeting.
- Avoid moving both a parent and its child as separate roots or the child will receive the delta twice.
- Hole colliders live on the `HoleCollisions` layer and reference their owning part through `HoleData.part`.
- Placement-layer preview objects must not be treated as normal selectable targets.
- `Assets/Scenes/Main copy.unity` is not the active production scene.
- Unity-generated `.meta` files must accompany every new asset.
- Preserve unrelated work in the working tree. Build products and `Library` are generated artifacts, not source.
