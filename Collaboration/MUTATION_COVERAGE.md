# Connected-mode mutation coverage

The development switch is required. Only the rows marked supported may mutate a connected document. The offline editor retains its existing paths. This audit is a release gate, not a claim of complete collaboration coverage.

Participant administration is separate from document transactions and personal Undo/Redo. Revocation serializes with commits/resume, supports duplicate stable-ID requests after restart, and fails closed on storage errors. Both event transports give removed members terminal feedback; their accepted content and other members' histories remain intact. The administration capability originated in 0.7 and continues in 0.8; atomic v1 migration preserves its revoked flag and original 0.7 archives can be restored forward. Dedicated CLI administration lists inactive memberships and reads a private owner capability file; it creates no administrative membership. No admission policy or person ban is implied.

Client mutations are `AddParts`, `SetPoses`, `SetParts`, `SetCustomMounts`, `TransformAndCopy`, `DeleteParts`, `SetChains`, `Undo` and `Redo`; create transactions carry reference-only `assetWrites` after authenticated durable upload. Only the authority can create `RestoreParts` inverse events; clients cannot supply inverse content. Unknown mutations fail. The authority does not accept a client author ID, run Unity physics or infer snapping. Creates require fresh stable IDs; a chain carried by `AddParts` or `TransformAndCopy` may reference only endpoints created in that same transaction, so fresh endpoints need no pre-existing lease. New geometry is validated and persisted by content hash before a custom part references it, and retained for undo/redo; duplicate instances reuse the existing hash. Pose writes preserve identity/catalog/paint/custom mounting state. `SetCustomMounts` can replace only a custom part's ordered mounting component; its geometry hash, pose, identity, state and paint must exactly match the accepted part. General `SetParts` writes cannot change custom geometry or mounts. Every ordinary existing write needs the owning live lease and expected entity version. Other chain edits additionally require expected versions and leases for every existing endpoint. Private mechanism results require the exact document revision used to evaluate them. Helper/client version 0.9.0-alpha is checked at startup and join. History checks part/chain reservations atomically and refuses to overwrite another participant’s edits. Durable rooms persist geometry, mounting layouts, receipts, identities and personal history across restart; ephemeral rooms retain them only in memory. Explicit Leave revokes that membership. Restart clears leases/access sessions/ghosts. Participant pending IDs are saved before submission and resolved without automatic replay. Preview geometry has no SavedObject, collider, detector or save ownership. Main scene wiring is installed at runtime rather than serialized into the production scene.

Explicit chain route edits retain stable entity IDs through `SetChains`. Version 1 cyclic order and per-member wraps survive copy/remap, accepted saves/exports, remote materialization, deletion, personal history and restart recovery. Legacy unordered routes and hashes remain compatible. Route editor previews are private; Apply reserves endpoints and supplies entity/chain versions. New route metadata is structurally strict, while Unity validates planar geometry and signed motion. See [CHAINS.md](../CHAINS.md).

Geometry transfer is outside document mutations: `HEAD/GET/PUT /assets/{hash}` authenticates each request and buffer, rejects viewer uploads and revoked memberships, and serializes publication through the room gate. Uploads never increment the accepted revision or enter Undo/Redo. A failed or canceled create can leave an unused immutable asset within the explicit 16 MiB/16-upload allowance; no garbage collection or history compaction is provided. Clients hydrate and validate reference-only snapshots before scene editing. Remote events wait for required assets without buffering geometry on the event channel. Accepted saves/exports include full geometry; source paths never travel to the authority. SQLite/archive v2 preserves required assets and retained histories; original 0.7/v1 restore migrates atomically. See the README for quotas, measured local results, original-catalog startup and forward-only compatibility.

Dedicated multi-room hosting adds no document mutation. Server-admin creation validates and atomically publishes a fresh room; offline registry restore preserves an archived identity and history. Every document/preview/lease/asset/membership/owner/receipt/history operation resolves the exact room first. Capability discovery and Unity joins select a room explicitly; caches remain origin/room/catalog/generation scoped. Process budgets reserve capacity before durable asset/edit publication and roll back failed writes. `MultiRoomChecks` / `MultiRoomFailureChecks` cover cross-room credentials, geometry and independent histories, plus failure isolation and restart; `CollaborationMultiRoomValidation` checks real scene joins/materialization/saves. Protocol 0.9 retains document/SQLite/archive v2 and forward paths from original 0.8/v2 and 0.7/v1. Online backup and live destructive room deletion remain unavailable.

Connection progress/cancellation is local presentation and lifecycle behavior. Host/Join/Resume/Reconnect cancellation preserves the pre-connection accepted scene and file association; returned membership credentials remain recoverable. Join publishes its candidate document after geometry hydration and pending receipt resolution. Unity defers queued shared frames while reconnect is pending, discards them on cancellation, and loads the accepted synchronized snapshot on retry. Connection Cancel does not submit an inverse, revoke membership or replay an unresolved edit. The shared-client connection tests and real pointer/Escape Unity smoke validate these boundaries; storage/wire versions and mutation authority remain unchanged.

Diagnostics v1 adds no document mutation or migration. Optional `diagnosticsVersion: 1` preserves protocol 0.9/v2 data and older helper joins. Read-only owner authorization deliberately avoids presence updates and remains available after a storage freeze; participants get local connection metadata only. Server administration remains separate from room ownership. `DiagnosticChecks` covers real CLI commands, malicious reflected errors, cross-room credentials, usage/quota semantics and unavailable registrations; the actual Unity UI smoke covers export/Cancel/Escape/failure, resource refresh and unchanged scene/file/save/membership/connection state. Detailed memory measurements are process-admin only and distinct from logical content accounting. Field acceptance remains pending.

Explicit short polling changes event delivery only. Optional capability v1 and strict `wait=0` use the same exact room/session/cursor and reference-only batch checks; mutations, leases, receipts, geometry/history and saves keep their authority. Clients pace one read at a time (250 ms active / 1,000 ms idle minimum delay), cancel reads/delays and use the established pending-receipt reconnect path. Older helpers refuse the selection before admission/cache access. `ShortPollingChecks`, three-transport bot/multi-room conformance and actual Unity selection/diagnostics/materialization/save/reconnect/leave cover local behavior; cross-OS/public proxy/service acceptance remains pending.

Explicit outbound proxy configuration adds no shared mutation or wire/storage migration. All transports and protected HTTP paths use the same per-client handler, including redirect-disabled WebSocket upgrades. Proxy credentials use only a proxy-scoped Basic challenge, separate from room/password/membership/owner/admin credentials. Fixed response-code projection prevents reflected error text reaching receipt feedback, UI, logs or diagnostics. `ProxyChecks` and actual Unity proxy/connection controls cover failed and canceled routes/transfers, generation fencing, unchanged accepted scenes/local files, preserved membership/pending outcomes and explicit receipt recovery without command replay. System/Direct/private HTTP-proxy configuration and exact limitations are documented in `NETWORK.md`; field acceptance remains pending.

Admission/backoff adds no shared mutation. Only capability/health and explicit operator GETs plus existing content-addressed immutable geometry transfers opt into three-send bounded retries. Admission, commits/history and admin mutations are single-send even after definitive rejection or lost reply; doctor stops subsequent transport admissions after failure. Event cursors are never silently restarted. Standard optional hints/fixed HEAD rejection headers need no schema migration, and old-helper defaults remain supported. A three-minute connection deadline and cancellable waits retain accepted scene/file bytes/saved state, known membership/scope and pending IDs; an already-sent admission retains its ten-second settlement rule. Actual Unity Cancel/Close/Escape/wait/exhausted/cooldown controls and CLI/server tests cover no extra admission/publication, no pending command replay and healthy-room isolation. See NETWORK.md for exact retry/manual-cooldown limits; field acceptance stays pending.
