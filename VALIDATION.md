# Protobot Rebuilt Validation Map

This is the validation and build companion to the main [Protobot Rebuilt Context Map](CONTEXT_MAP.md). Keeping commands here lets contributors load architecture and workflow context without automatically loading the full validation catalog.

## Selecting validation

Choose checks after inspecting the change and identifying the affected subsystem in the main context map. Search this file by subsystem, validation class, or changed script name; loading unrelated entries is unnecessary.

- Start with the smallest validation suite that directly covers the changed behavior.
- Add a referenced shared-path regression only when that shared path changed, the targeted check exposes a related risk, or the change spans both features.
- Use compile, player-build, rendered, native-dialog, collaboration-lab, cross-platform, and release-acceptance checks only when the changed artifacts or requested deliverable require them.
- Do not treat every suite mentioned by a validation description as an automatic checklist. Record what ran and any checks that remain environment- or platform-dependent.
- Finish applicable source and scene changes with the lightweight repository checks described below, including `git diff --check`.

## Development collaboration

Enable **Tools → Protobot → Collaboration → Enable Development UI** for Play Mode. Collaboration development players expose the button on normal launch; other players require `--collaboration`. The controller is installed at runtime; Main.unity is not migrated. Export the compatibility catalog through the same menu and publish the matching self-contained helper with `Collaboration/publish.sh` or `publish.ps1`. Host/Join supports catalog builds, bounded custom models with ordered live-edited mounts, and valid chains: placement/snapping, G/R/transform handles, Move/G → H/Connect, paint/Default, catalog property regeneration, custom import and mount editing, Alt copies/P/paste/import, deletion and C-key chain add/remove. Simulation mouse/numeric/timeline previews remain private; click/Enter/Set pose publishes one reserved accepted pose. Shaft-position buttons reuse resolved movement/rotation math. Undo/Redo routes to personal authority-owned history (persisted for durable rooms) and refuses to overwrite another participant’s later edits. G/R reserves the complete frozen write set before preview and commits only at `KeyboardTransformTool.CompleteConfirmation`; `Placement.Place` and `ObjectDeletor` use their actual confirmation boundaries. The delayed legacy state notification never publishes network edits. Incoming batches refresh world poses/detectors/chains and repair invalid selection on Unity's main thread. Cameras and file associations remain local.

`BuildsManager` saves the accepted document via `CollaborationSession.SaveSnapshot`, waits submitted outcomes and main-thread application, and records an independent captured hash. Previews cannot enter shared local saves; newer remote revisions remain dirty after an async write. Hosting retains the current path; newly joined or explicitly reopened recovered documents use Save As. Join/Open/New use normal unsaved handling. Network loss freezes shared edits; explicit reconnect resolves receipts and resynchronizes. Continue offline forks the last accepted scene. Closing an owned helper's private stdin ends only that process; independent CLI servers are unaffected. In-app hosting creates a private room directory through `CollaborationRecovery`; `RoomStore` commits SQLite journal/receipts/history before ack, periodically checkpoints, and fails closed on corruption or write failure. `RecoveryFiles` atomically saves scoped client resume credentials and pending IDs before send. Reconnect restarts a dead owned helper; recovered rooms are listed without a listener and require explicit Resume with a matching catalog/version. Explicit Leave revokes membership before closing the helper, while application Dispose retains the cache. Self-contained dedicated-server publishes support `linux-x64` and `linux-arm64`; the deployment guide maps `uname -m` to the correct artifact. No backup/migration/multi-room administration is implemented.

Helpers and clients require `CollaborationProtocol.Version` (currently `0.7.0-alpha`). The launcher checks readiness; clients check capabilities and the authority validates join versions. Export Catalog writes built-in part/parameter validation rules and a conservative generation-source fingerprint, not the current build. Custom geometry is validated from the versioned document rather than added to the catalog. Player builds export/bundle the catalog automatically.

`LocalPreferences` wraps the existing settings/rebinding/recent-directory paths. `--collab-profile <directory>` acquires a per-process profile lock and uses an atomic JSON store; failure never falls back to normal user settings. `CollaborationArguments` excludes recognized values from startup build-file scanning. Supply separate `-logFile` paths when launching multiple players. Passwords/tokens never belong in command arguments or invitations.
